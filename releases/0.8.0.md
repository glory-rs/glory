# Glory 0.8.0

Glory 0.8.0 adds an explicit, finite plot-pointer event channel for shared
Rust chart widgets across browser and native Apace hosts. All 16 owned
packages use the coordinated 0.8.0 version and internal dependency minimum.

## Breaking API change

`glory-render::Event` and `EventKind` gain a `PlotPointer` variant. Applications
that match these enums exhaustively must handle the new variant. This change
uses a new minor version rather than a patch release of 0.7.

`PlotPointer`, `PlotPointerDevice`, `PlotPointerPhase` and
`MAX_PLOT_POINTER_COORDINATE` describe validated local coordinates and finite
pointer observations. `Render::supports_plot_pointer` defaults to false;
`Scope::supports_plot_pointer` exposes explicit host support. Ordinary pointer
events retain their existing contract.

## Hosts and runtime

- Browser and Apace hosts observe explicitly subscribed physical View
  viewports. The runtime validates the origin, payload and host support before
  dispatching the event. Leave and cancellation participate in cleanup.
- The release also includes the fixes delivered since 0.7.0 for retained child
  ordering, WebView host inbox delivery, browser translation, native file
  loading, streamed SSR responses and CLI development serving.
- Release verification respects each registry consumer workspace's Cargo
  metadata target directory and records that directory in its evidence.

## Requirements and verification

Rust 1.95 remains the minimum supported compiler. The coordinated external
engines remain Takia 0.15.1, Wingy 0.31.1 and Apace 0.3.0, with the exact
support versions recorded in `docs/engine-forks.json`.

The release workflow gates publication on the repository's Linux, Windows,
MSRV, dependency and browser checks. The publisher verifies immutable Git
provenance, package checksums and a registry-only DSL/SSR/native consumer.
Optional Apple and actual mobile-device, OS IME and screen-reader acceptance
remain separate from those checks.
