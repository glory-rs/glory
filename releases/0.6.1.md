# Glory 0.6.1

Glory 0.6.1 is the coordinated Rust 1.95 release of the owned reactive runtime,
shared Widget model, HTML display templates and replaceable rendering hosts.

## Application APIs

- Rust builders and the optional XML-like `view!` syntax implement the same
  `Widget` contract. Raw HTML uses checked shared templates and dynamic slots.
- `Each` uses one API for vectors, `Vary` and generational `KeyedList` members;
  keyed children preserve their mounted state through movement.
- `Cage`, `Bond` and `Vary` retain Owner-scoped lifetimes. Field and collection
  projections, resources, tasks and requester-owned query replies follow the
  same disposal and cancellation boundaries.
- Routing provides typed targets, retained nested layouts, explicit history
  providers and SSR/hydration integration. Fluent localization remains opt-in.
- Browser, synchronous SSR, progressive HTML streams and native Widget hosts
  share HTML mapping and typed control behavior. Apace and the system-WebView
  host retain their separately documented capabilities.

## Project tooling

- The project-owned CLI supports binary and feature overrides, disabled default
  features, native application arguments across watch restarts, JSON Cargo
  build plans and shell completion.
- Release Web builds can use an explicitly pinned Binaryen executable. Version
  mismatches and optimizer failures preserve the last accepted output.
- The project README now links concise setup/examples to detailed runtime,
  host, CLI and verification guides.

## Compatibility and verification

The coordinated dependencies are Takia 0.15.1, Wingy 0.31.1 and Apace 0.3.0,
including their independently versioned support crates. The maintained Stylo
source is published as the `glory-stylo` 0.22.0 family and its namespaced support
packages, preserving its Servo text-fill behavior without Git dependencies or
consumer Cargo patches. Cargo uses resolver 3.
Library/example/benchmark lockfiles remain generated locally; release checks
retain their checked resolutions and publication evidence.

The release workflow requires dependency auditing, Rust 1.95 compatibility,
portable Linux checks, Windows host checks and actual browser acceptance before
publication. Packaged registry-only consumers are checked independently of the
sibling-source build. Platform compile checks do not establish real-device,
OS IME, screen-reader speech or application-store acceptance.

The GTK3 WebView dependency retains GLib 0.18.5 and RUSTSEC-2024-0429. The
repository's reviewed audit policy reports that exact version/advisory as a
visible warning; it is not claimed fixed. Other vulnerabilities, unsoundness,
yanked dependencies and auditor failures remain blocking.

This series contains breaking changes from the older Glory APIs. Use the current
Widget/Cage/Bond/Vary and routing APIs; retired runtime, server-function and
adapter aliases are not restored. Consult the implementation ledger and adapter
guides for precise supported operations and remaining platform boundaries.
