# v2 Plan 提交准备与暂存日志优化

日期：2026-10-28。基线：远端 `v2` 的 `cb7ebdda33b51dd53171ea33b51372112ca0d134`。
候选：本轮工作区源码，证据中的 `candidate4`。两者均为 Glory 0.3.1；Dioxus 锁定 0.7.10。

本轮同机对照确认了局部脚本收益：**清空千行 Script 中位数下降 27.1%，万行创建下降 4.4%**，
两项四轮都朝同一方向改善；追加合并中位数改善 5.9%，但仅两轮改善。
千行创建与替换基本持平，删除行的小操作有回退。**没有确认整页两 RAF 总耗时提升**：
万行从 418.85 变为 426.05 ms。保留这组提交准备／表示优化，不把它称为整体应用提速。

## 实现

继续沿用[Plan 宿主批量提交原型](v2-plan-host-batch-prototype-2026-10-28.md)，保留
Cage/Bond/Vary、UI 和 Mapper 两份 Memory、每个语义节点的完整身份与属性、实际 DOM 工作。
此次没有改变业务代码、benchmark 布局、依赖、功能开关或 workload。

- **共享声明事实。** Plan 构造时计算有限提交类型适用性；文档原型保存物理适用性和部件总数。
  实例仍验证身份、拓扑、当前字段、放置、退休条件及预算。弱声明缓存原有边界不变，
  不缓存实例状态或业务 key。
- **紧凑宿主对象表。** 一个提交段只复用当前新建实例的 bank 引用、最近原型和最近挂接目标。
  引用仅在该段内有效；既有实例仍使用自己的地址。身份十进制字符串直接写入同一 UTF-8 区，
  ASCII 身份按字节增量推进 UTF-16 单位，其他动态文字仍正确计算 UTF-16 长度。
  创建用 Entry 在一份连续列表登记，确认记录只保存数量，避免每实例另建 Vec 和重复 Rc 存储。
- **连续回滚日志。** 原始 generation、水位关联身份、移出的模型节点和 HTML key 按段连续保存，
  每个操作记录自己的范围。失败从后向前排除后缀；创建验证失败先截断新增 generation 日志。
  保留字段逆操作和 metadata sharing 恢复、成功前缀、旧槽复用、跨实例邻接恢复和 Faulted 行为。
- **按需创建 bank。** 纯字段和纯退休段不再创建没有用途的 JS 数组。

每段原有的 256 个语义操作、4096 个计费模型节点、4096 条物理记录和 64 KiB 字符串 payload
限制继续有效。受控输入、已连接移动、聚焦退休和不支持操作沿原有有序回退路径执行。
每段 Packet 独立；本轮没有保留曾试验的跨段缓冲区复用。

## 最终九项结果

ScriptDuration 中位数，单位 ms。改善列正数表示候选更快，负数表示更慢。

| 操作 | 原 v2 | 优化后 | Script 改善 | Dioxus 0.7.10 |
|---|---:|---:|---:|---:|
| 创建千行 | 18.156 | 18.179 | -0.1% | 4.966 |
| 替换千行 | 27.004 | 26.935 | +0.3% | 8.959 |
| 更新每十行 | 0.882 | 0.867 | +1.6% | 1.179 |
| 选行 | 1.178 | 1.109 | +5.9% | 1.059 |
| 交换行 | 0.663 | 0.667 | -0.5% | 1.186 |
| 删除一行 | 0.621 | 0.656 | -5.8% | 1.083 |
| 追加千行 | 16.777 | 15.785 | +5.9% | 5.591 |
| 创建万行 | 168.736 | 161.322 | +4.4% | 41.602 |
| 清空千行 | 21.000 | 15.303 | +27.1% | 4.016 |

千行创建／替换没有实质提升；删除行增加约 0.036 ms，原始回退保留。
选行等小操作的百分比不能单独推广为稳定优势。Dioxus 的批量脚本时间依然更低，
此处沿用仓库的父列表组件组织，未重跑独立行组件变体。

## 正确性、GC 失败调查和验收边界

最终代码通过：

- render/html/web/ui/ssr 的 all-feature **548 项**相关 Rust 测试；此前 Core 回归也通过。
- 相关 native／WASM all-feature all-target Clippy、应用和完整 Web fixture 的 WASM Clippy。
- **31 套真实 Chrome 验收**与重建 stream_fixture 的传输检查。
- 六张 PNG 跨三者一致，查看了最终万行中部图；存续 Element/Text／Glory 语义身份、全部万行真实矩形一致。
  Glory 清空后回到 UI 10／graph 3；Dioxus 只检查 DOM，不声称其内部图资源清理已获证明。
- 新增 600 实例跨段创建／字段更新，以及跨段中途失败后保留 601 个已确认行、停止后续新实例并清理的用例。
  generation 创建失败后的日志对齐另有 Rust 回归。原有 memory.grow、UTF-16 选区／组合态、
  聚焦退休、部分退休和每个成功前缀的断言保持。

GC 验收曾两次独立失败，另在预热浏览器连续 8 次运行中复现 4 次，全部失败记录保留。
Heap snapshot 显示强路径为 HTMLDocument／app 的 **LayoutResult→PhysicalBoxFragment→LayoutBlockFlow→旧行**，
旧行直接入边为布局对象、DOM 后代和 WeakRef；未见 bank 数组强引用。
当时四轮强制 GC 前未等待删除后的浏览器布局生命周期。

修正只在该验收中置前页面、等待两个 RAF，然后保留原来的四次 GC 和全部释放断言；
同一预热浏览器连续 8 次通过，最终整套 31 验收也通过。该修正不进入正式计时 harness，
不改变已经构建的 benchmark WASM。堆快照和保留路径位于本轮 `retainers-warm-browser/`。

本轮未运行含 Blitz／各平台门禁的完整 canonical 脚本，不改变原型报告中既有 native 门禁的结论。
