# Glory 渲染流程架构改进与验证

日期：2026 年 10 月 26 日。

本轮按[架构复核报告](/D:/Works/glory-rs/glory/docs/render-pipeline-architecture-review-2026-10-26.md)落实了生命周期维护、浏览器节点初始化和能力更新依赖三项整理。**保留这些改动的依据是职责集中、重复规则减少和行为一致。性能没有建立稳定的整体优势，不能将本轮描述成全面提速。**

UI 的暂存 Memory 与 Mapper 的独立 Memory、完整身份、Owner 关系、校验、查询屏障和成功前缀契约保留。没有增加通用指令 VM、跨 mutation 回滚日志、持久脏节点缓存或新的构造协议，也没有裁剪能力或更换响应式粒度。

## 1 再次复核后的实施取舍

| 报告建议 | 本轮结果 | 架构依据 |
|---|---|---|
| 统一 UI 退休清单 | 已实施 | 由本层 Memory 定义实际退休节点，UI 按结果清理附属索引 |
| 集中登记、替换和移除规则 | 已实施 | 正向、反向索引及计数在 Present 内维护，调用方负责业务前置校验 |
| 合并所有 NodeId 附属记录 | 未采用 | 普通节点与事件、查询的密度不同，继续保留稀疏表 |
| 共用 Entry 基础初始化 | 已实施 | 默认状态只有一个来源，宿主创建和 adoption 的差异保持显式 |
| 明确能力更新依赖 | 已实施保守分类 | 一次提交的临时摘要描述影响范围，具体驱动保留自己的状态和执行逻辑 |
| 精简实验脚手架 | 已删除恒真的 DEEP_CLONE 开关 | 普通 fallback 仍由结构和预算决定，不保留未使用的运行模式 |
| 继续调整实例登记和临时分配 | 完成复核，本轮不增加新结构 | 声明、Shape、原型和分页身份存储已共享；不为省一次短 ID 数组复制引入新的共享实例层 |
| 完整宿主提交计划 | 继续暂缓 | 尚未形成需要独立 API 的构造单元，不隐式重排现有操作 |

“统一维护入口”没有演变为一个跨层管理器。Owner 和响应图仍归 core；应用的节点、订阅和请求索引归 ui；HTML 映射归 html；物理对象和能力驱动归 web。

## 2 UI 生命周期以 Memory 的退休结果为准

原流程先由 UI 手写遍历清理附属状态，再让同一份 UI Memory 遍历并销毁节点。现在使用已有的 `Memory::dispose` 返回实际退休身份清单：

```mermaid
flowchart LR
    A[按原规则选定退休根] --> B[UI Memory.dispose]
    B --> C[返回本次实际退休身份]
    C --> D[Present 清理节点及附属索引]
    D --> E[排入原有语义 Dispose]
    E --> F[退出借用后释放回调和请求捕获]
```

退休根选择、disposal boundary、跨 Owner 放置、挂起后代和语义 Dispose 数量均保持原规则。Mapper 随后仍从自己的树独立执行 Dispose，没有将 UI 清单当成适配器的校验凭据。

Present 现在集中维护节点登记、Owner 兴趣提取、监听器登记与撤销、查询登记与移除，以及单个已退休节点的索引清理。普通 Create 和 Plan 创建共用节点登记规则。监听器替换返回旧捕获，回调和查询捕获在离开 Present 借用后析构。

节点创建者、监听器登记者和查询请求者仍是三个独立关系。按 Owner、节点和 token 定向处理，不扫描全部查询或业务数据。

返回清单需要与本次退休节点数成正比的临时存储。它统一了枚举规则并减少一次树遍历，**不等于已证明分配次数或峰值内存下降**；没有为此再增加一个长期保留的大缓冲。

实现：[Present 登记入口](/D:/Works/glory-rs/glory/crates/ui/src/app.rs:94)、[退休节点清理](/D:/Works/glory-rs/glory/crates/ui/src/app.rs:193)、[Owner 清理编排](/D:/Works/glory-rs/glory/crates/ui/src/app.rs:462)。

## 3 浏览器节点共用纯状态初始化

`Entry::new` 统一初始化部件、边界、父节点、编辑状态、兴趣集合和可选观察器等 Rust 数据。它不调用 DOM。CSR/Plan 传入新控件状态；adoption 传入已观察到的组合态。

新控件的属性回放、Select 构造，以及 adoption 的脏值检查、组合态读取、indeterminate 恢复仍在各自路径执行。没有为了共用代码让 hydration 重写已有输入、选择或组合态。

实现：[Entry::new](/D:/Works/glory-rs/glory/crates/web/src/browser/dom.rs:143)、[adopt](/D:/Works/glory-rs/glory/crates/web/src/browser/dom.rs:396)、[make_entry](/D:/Works/glory-rs/glory/crates/web/src/browser/dom.rs:726)。

## 4 能力更新使用本次提交的影响摘要

原来的借用元数据表扩展为 `Batch { metadata, state }`。同一次 Mutation 遍历同时提取当前树中的元数据和有限影响标记，生命周期止于一次 Renderer::apply。标记不保存节点历史、业务值、回调或 DOM 对象。

| 影响 | 触发来源 | 当前用途 |
|---|---|---|
| 结构 | Create、CreatePlan、Place、Resume、Suspend、Dispose | 保守重查继承状态和文件权利 |
| 输入可用状态 | Enabled、Role、Semantics | 重查祖先 enabled、hidden、inert、readonly 等影响 |
| 焦点策略 | Focus | 更新 Rich 的 tabindex 等状态 |
| 富文本文档 | RichDocument | 保留受控文档和版本协调 |
| 文件配置 | File | 撤销旧配置版本的选择和读取权利 |

Patch 匹配是穷尽的。新增变体时，编译器要求重新决定它的影响分类。Role 参与 inherited enabled 规则，因此保守归入输入可用状态；合法组合仍先通过语义校验。

具体调整为：

- Rich 在无相关影响时跳过整个活跃集合核对；原生编辑观察仍由观察阶段处理。
- 文件选择及读取权利在结构或配置变化后协调；ClearFiles、RemoveFile 等动作的直接清理路径保留。
- FocusScope 的语义声明在结构或继承状态变化时重建；弹层的物理同步继续执行，文本和 CSS 引起的几何变化仍会处理。

相关变化仍可遍历当前活跃控件集合。本轮只消除无关提交触发的工作，没有引入复杂的祖先订阅网络或逐节点脏调度器。

摘要对拒绝后缀允许保守多做检查，读取的元数据来自 Mapper 当前树，不安装被拒绝的载荷。既有故障状态、模型处理进度与宿主成功水位的区别保持不变。

实现：[临时摘要](/D:/Works/glory-rs/glory/crates/web/src/semantic_changes.rs:12)、[Rich 更新边界](/D:/Works/glory-rs/glory/crates/web/src/browser/rich.rs:421)、[Layers 更新边界](/D:/Works/glory-rs/glory/crates/web/src/browser/layers.rs:54)。
