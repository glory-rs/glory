# WASM strip 与静态宿主适配：2026-10-30

本轮是 0.6.0 发布后的工作区候选优化，尚未发布新版本。
已发布的 tag、crate 和 2026-10-29 benchmark 原始数据保持不变。
比较使用上轮冻结的标准 HTML 表格 fixture：Glory 0.6.0、Dioxus 0.7.10，
两者均由 Rust 1.98.0 和 wasm-bindgen 0.2.129 重新构建，没有额外运行 wasm-opt。

## 相同的构建设置

```toml
[profile.release]
opt-level = 3
debug = false
lto = true
codegen-units = 1
panic = "abort"
strip = "symbols"
incremental = false
```

Glory workspace 的 release profile 启用 `strip = "symbols"`，保留原有 `opt-level = "z"`。
性能 benchmark 的独立 workspace 使用上述相同配置；display-web 示例也开启符号剥离。
`benchmarks/wasm-size` 是显式保留名称的诊断探针，继续使用其记录在案的配置。
Cargo 只读取应用 workspace 的 profile，依赖库的 profile 不会替应用设置 strip。
见 [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html#strip)。

统一配置后，最终候选相对 strip 基线再减少 319782 字节（43.8%）。
最终 WASM 比 Dioxus 大 7.53%，Brotli 大 1388 字节（1.29%）。
WASM 加实际 JS 图合计：Glory 437944 字节，Dioxus 432165 字节；
逐文件 Brotli 合计分别为 115634 和 117330 字节，Glory 小约 1.45%。
这些数值描述本 workload 和这一轮构建，不代表任意应用的框架固定成本。

JS 侧也应计算实际加载图：Glory 是 18807 字节 bindgen 入口加 8769 字节模板宿主；
Dioxus 是 27807 字节入口、20855 字节 interpreter 和 1887 字节属性辅助脚本。
两者将宿主逻辑放在 WASM/JS 的位置不同，只看 WASM 会漏掉这一部分。
Glory 另生成的两个未引用 inline 脚本合计 6905 字节，本 fixture 不加载，
已在分析器的 unreferenced 列表单列；它们影响分发目录占用，不计入实际首载 JS 图。

单独重建标准仓库中使用 registry Glory 0.6.0 的独立条目，strip 后为 731084 字节。
它使用该条目自己的 model 模块，和上轮冻结 fixture 存在源码位置/模块组织差异，
因此不混入本轮前后性能配对。其预构建文件只包含已发布 runtime，未替换成未发布优化版。

实际重建会产生非 custom 段的少量差异；不能用从旧文件直接删除 name 段来代替重建。

## 代码和静态数据去了哪里

下表从实际参与比较的 strip 产物读取，包含各段编码头：

| 段 | Glory strip 基线 | Glory 最终候选 | Dioxus |
|---|---:|---:|---:|
| code | 683883 | 383425 | 341515 |
| data | 42264 | 23268 | 34055 |
| custom 合计 | 451 | 451 | 504 |

静态宿主适配去掉 300458 字节 code、18996 字节 data。
最终 Glory 的 data 已比 Dioxus 小 10787 字节，code 仍大 41910 字节。
最终 custom 段只余 wasm-bindgen 所留的少量 `name` 和 `producers` 信息，
剩余整包差距主要来自 code，不能再归因于先前约 153KB 的符号名称表。

实际 data payload 为 Glory 23244 字节、Dioxus 34032 字节。
Glory 可读字符串扫描约 11243 字节，包含错误枚举/诊断、模板声明与槽位/属性校验、
测试业务词表、panic/格式化常量和依赖源路径，其余还包含二进制常量与布局/指针数据。
Dioxus 同样保留诊断、hook/suspense 错误、业务词表、panic 常量与源路径，
可读字符串约 16397 字节。字符串扫描不是符号级归因，不能据此把其余字节都称为业务数据。

旧的 `view::mounting` 用一个 Ui/Sparse 枚举承载宿主。在 Each 的结构回调中，
编译器无法把捕获的枚举持续视为 Sparse，因而把 Ui 行挂载、Scope 的语义清理、
Memory 渲染、描述符和事件校验等未执行路径一起保留在纯 HTML 表格中。
辅助符号构建可见 `Memory::apply`、`DescriptorView::validate_fields` 等大函数，
以及文件/图形/选择控件的完整校验消息。

现在配置动作和内容安装以内部宿主类型作为编译参数；Each/Show 仍执行原来的共享控制器。
UiContent 和 SparseContent 分别保存原有宿主资源，行所有权、弱引用、挂接和错误处理契约不变。
纯 HTML 程序能消除未使用的 Ui 路径；混合程序继续按需保留完整语义路径。
冷错误格式化试验另加 `cold`/`inline(never)`，减少 2928 字节；交替复测后保守撤回，
最终源码仅保留静态宿主优化。两者的完整证据分别保存，未用最小试验产物冒充最终结果。

## 剩余代码热点与下一步

有符号辅助构建用于定位调用链。它与正式 strip 产物的非 custom 哈希不完全相同，
因此不跨二进制套用函数索引，也不把其分组当作正式产物的精确 crate 大小。
每个函数体只计入其外层符号一次，内联调用者的成本属于该外层符号；分组并不表示可独立删除的字节数。

辅助构建中，候选的 `glory_render` 外层符号组从约 126.8KB 降到 4.6KB；
后者主要是错误类型格式化。剩余值得测量的部分包括：

- BTree 集合实现约 57.3KB、47 个函数体；Dioxus 对应约 13.3KB、13 个函数体。
  Glory 的成员字段、别名和 Owner 元数据需要多种键值实例化，优先考虑共享内部存储的代码，
  同时保留零/单元素内联和大集合查找/删除复杂度。
  具体入口是 `core/src/fields.rs` 的 roots/aliases/indices/targets，
  以及 `core/src/sparse.rs`、dependencies/subscribers 中的少量元素特化；
  这些结构存放运行时身份、投影、订阅和 Owner 信息，不能当作重复的业务行镜像删掉。
- Hash 集合实现约 22.4KB，Dioxus 对应约 14KB。需要区分真实运行时索引与泛型实例化成本。
- 模板编译相关外层符号约 7.2KB；可继续研究静态 DSL 的编译前移，但应复用现有检查编译器，
  保留动态/手写入口、声明校验、预算和缓存语义。
- Each 安装闭包、KeyedList 修改、响应式字段退休仍是较大的热函数。
  辅助构建中 `Model::action` 约 23.5KB、Each 安装闭包约 18.5KB、
  `State::flush` 约 9.1KB、`Runtime::ensure` 约 6.5KB；部分集合成本已经内联在这些函数中。
  减少内联或改变容器必须同时测 CPU 和清空/复用行为，不能只按字节数决定。

本轮保留现有集合算法、BindingId 列表和 KeyedList 的零镜像表示；没有更改公开 Widget/Each API。

## 冷错误格式化试验为何撤回

首次完整 45 项采集使用额外冷错误格式化标记，清空脚本均值从 strip 基线的
49.21ms 增至 57.65ms。没有据此丢弃慢样本，也没有直接认定错误路径是清空热点。
随后按三种顺序交替运行三版本，每版本每轮完整采集 15 个清空样本：

| 清空脚本均值，ms | strip 基线 | 静态宿主（保留） | 加冷格式化标记（撤回） |
|---|---:|---:|---:|
| 第一轮 | 56.92 | 55.73 | 56.05 |
| 第二轮 | 51.79 | 46.10 | 50.27 |
| 第三轮 | 57.17 | 54.23 | 56.67 |
| 各 45 个样本合并 | 55.30 | 52.02 | 54.33 |

首次清空回退没有稳定复现；三轮中冷标记版又均略慢于仅静态宿主版。
样本标准差约 15–18ms，不能把差值直接解释成错误辅助函数在正常清空时执行。
源码检查也未发现正常清空必然执行这些格式化函数。考虑其仅再省 2928 字节，
最终保守撤回标记，重建并按完整相同 benchmark 重新比较最终版本。

## 正确性与测量边界

- 工作区 all-feature 测试 1131 通过、2 忽略；Native/WASM all-target Clippy 均通过 `-D warnings`。
- 手写与 DSL 的相同 DOM/像素、600 行、Vary/KeyedList、多根范围、同 key 更新、
  子状态与节点身份、8 轮清空、弱引用 GC、故障清理通过；普通 counter/list 示例通过。
- 混合 CSR/水合检查通过，包括脏输入/选区、错误 shell 拒绝、函数工厂、原始事件、列表身份和焦点。
- 真实 gated Rust HTTP 流检查通过，包括增量字段、表格 Each、Show、组合输入延迟 End、
  最终同 DOM 水合、错误声明/槽值拒绝和断连清理。
- Sapid 的两个原生 mixed_dsl 检查通过，覆盖实际布局、输入、keyed 移动、CPU 绘制和清理。

标准对比使用冻结的上游 runner、相同 Chrome 和 CSS，比较 strip 基线、候选、Dioxus 三个变体。
默认 CPU 每项 15 个样本，选择 25 个，memory/size 每项 1 个，保留全部慢样本和失败重跑记录。
三个变体均通过标准 keyed 检查。完整结果附于下节，单轮小差异不作统计显著性结论。

## 最终保留版本的完整标准对比

已采齐 45/45 个结果文件。唯一缺失的 strip 基线更新项发生 Chrome `No commit event`，
以原 runner 的完整默认样本重采一次成功；44 个成功文件未替换。
输入文件 SHA256 在计时前后相同；编译观察共 259 次，均无 Rust 构建进程。
Chrome 155.0.8059.86，runner 冻结于 `4015e28829e45679e3ea13cbfc1558a03bc64479`。

下表是单轮均值，单位 ms，单元格为 **总时长 / 脚本时长**。
默认更新/追加/清空归一化和 CPU 降速规则均保留；并非未降速的 Rust 函数独立耗时。

| 项目 | Glory strip 基线 | Glory 最终保留 | Dioxus 0.7.10 |
|---|---:|---:|---:|
| 创建 1000 行 | 44.81 / 7.65 | 45.81 / 8.02 | 45.63 / 8.19 |
| 替换 1000 行 | 51.54 / 13.98 | 51.39 / 13.72 | 52.57 / 14.97 |
| 更新每十行 ×16 | 59.18 / 5.12 | 60.77 / 5.41 | 55.63 / 5.46 |
| 选择 | 25.62 / 4.32 | 28.15 / 4.18 | 25.11 / 2.12 |
| 交换 | 53.65 / 3.27 | 56.93 / 4.39 | 65.77 / 6.12 |
| 删除一行 | 37.87 / 1.45 | 34.79 / 1.39 | 33.83 / 2.29 |
| 创建 10000 行 | 524.64 / 92.64 | 519.45 / 92.63 | 551.75 / 102.20 |
| 追加 1000 行 ×2 | 54.18 / 9.23 | 57.10 / 9.61 | 57.42 / 9.83 |
| 清空 ×8 | 60.23 / 52.51 | 62.95 / 54.53 | 51.95 / 44.50 |

本轮创建 10000 行和替换基本持平，单轮创建/更新/追加/清空脚本均值略高，
选择和删除略低。选择和交换的总时间还包含帧调度/布局/绘制；不能用总时间差反推 Rust 热点。
交换脚本在这一轮偏高且方差较大，另做四轮相反顺序复测，保持每轮每版本 15 个默认样本：

| 交换脚本均值，ms | strip 基线 | 最终保留 |
|---|---:|---:|
| 第 1 轮 | 3.780 | 3.727 |
| 第 2 轮 | 3.647 | 3.620 |
| 第 3 轮 | 3.247 | 4.193 |
| 第 4 轮 | 3.433 | 3.533 |
| 各 60 个样本合并 | 3.527 | 3.768 |

前两轮相近，第三轮偏高，第四轮差 0.10ms；合并中位数是 3.0/3.1ms，
标准差是 1.44/1.65ms。原单轮约 34% 的升幅没有稳定复现，
合并均值仍高 0.242ms（6.85%），不能据此宣称零回退。
本轮明确获得体积下降和相同 API/复用行为；CPU 项目没有普遍加速，
也没有把这一组复测覆盖原完整一轮的结果。四轮计时观察 57 次，无编译进程。

## 复现与原始证据

本机证据根目录：`D:/BuildCache/glory-strip-size-20261030`。
`results/uniform` 保存 strip 基线，`results/typed` 保存最终静态宿主产物，
`results/optimized` 是历史命名的冷错误格式化试验产物（已撤回）；
`results/*-size.json` 保存 SHA256、段大小、压缩和 JS 依赖图；
`results/*named*attribution.json` 保存辅助符号定位；`results/source.patch` 保存最终补丁，

`standard-retained` 保存最终保留版本的完整对比，`swap-confirmation` 保存四轮交换复测。
