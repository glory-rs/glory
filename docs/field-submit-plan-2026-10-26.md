# 跨 mutation 字段提交计划（2026-10-26）

本轮将连续的、可局部恢复的字段 mutation 编译成有界宿主提交计划，JS 返回完成
位置，Rust 据此确认完整语义操作的成功前缀。它不再局限于单个 Patch 内的字段批。
响应式模型、两份 Memory、完整 NodeId、独立校验和现有物理节点身份均保留。

## 第一版边界

可合并类型为 `Patch::{Text,Label,Classes}`。它们不改变名称注册、资源、焦点范围、
输入版本或节点拓扑，可以使用现有字段逆操作精确恢复。创建、放置、挂起、销毁、
其他字段、受控 Property/Revision、查询和动作均形成原有提交边界，不向前挪动
后续字段，不延迟越过屏障。创建批、挂载区间和退休批尚未实现；当前不是将整份
Mutation 数组一次交给 JS 的通用解释器。

HTML Sink 显式选择字段批能力；SSR、Blitz 和普通记录 Sink 默认保持逐条执行。
Web 的 Plan 物理部件可跨节点批量写入，普通 Create/adoption 节点和超出数据包
预算的字段使用现有宿主路径。标量 mutation 保留快路，不额外建立回滚日志。

## 提交和失败契约

1. Mapper 收集最多 128 个连续、符合条件的 mutation。
2. 每项仍先经过 descriptor-local preflight，再通过 `Memory::prepare_patch`，
   在借用 guard 时纯映射出原有 HTML Edit。
3. 每个字段先完成语义 commit，再进行宿主工作。一个有界日志只保留所触字段的
   逆操作与原先 metadata override mask，不复制 Descriptor 或整棵 Memory。
4. Sink 将多个节点的物理字段打包，保留字符串、字段和语义操作的原始顺序。
5. JS 顺序执行并返回完成的物理字段数；Rust 使用每个 mutation 的结束位置，
   换算为完整成功的语义操作数，包括没有物理 Edit 的 Keep/等值更新。
6. Rust 逆序恢复未执行的语义后缀及其原先共享状态，并恢复统计和 receipt 到成功
   前缀。成功前缀保持；不声称已经发生的 DOM 写入可以回滚。宿主错误使 App Faulted。

若后面的语义字段拒绝，已准备的合法前缀仍先提交；若宿主在这个前缀中更早失败，
返回宿主错误。这里保持原先逐条执行时的错误先后关系。

日志在 drop/unwind 时恢复全部未确认修改。API 自身也有 128 项上限，Mapper 在
到达上限前拆批。输入版本、Semantics、Role 等具有其他状态影响的字段不进入这份
日志，继续使用原有 guard 和提交路径。

## 有界数据协议

一个物理写入使用五个显式 u32：对象表索引、部件地址、写入类型、名称结束位置、
值结束位置。类型只有文本、设置属性、移除属性；字符串位置是 UTF-16 code unit。
对象表通过借用的 `&[JsValue]` 传入，避免为每个目标调用 Array.push 或反向分配。
每包最多 512 次物理写入、64 KiB UTF-8 字符串；单项过大时回到原有路径，未缩小
应用可使用的文本/属性大小。

生成绑定将对象表变为 JS 自有数组，JS 在第一次 DOM 写入前复制有界 u32 记录。
这样原生回调重入并导致 WASM memory.grow 时，后续字段不依赖被分离的内存视图。
异常只在本次私有结果数组内暂存，不持久保存用户值、访问历史或退休节点。

## 正确性

新增 Memory 测试逐个验证接受长度为 0..4 的前缀，包括同一字段被反复修改；
比较正常逐条 apply 的值、共享 mask、统计和查询回复水位。另覆盖丢弃、unwind、
不支持的字段和日志容量上限。

Mapper 测试覆盖较晚语义拒绝、较早宿主失败的错误优先级、128 项拆批与 Role
屏障。Web 新增第 29 组浏览器测试：一个数据包内先写非 BMP 文本、更新另一个
节点的 class，再覆盖前面的文本；第一次写入期间增长 WASM 内存，仍完成后缀。
另一轮在 class 写入注入异常，确认标签前缀保留、后缀不执行、再次 flush Faulted，
并且故障 App 可以完整清理。

render/html/ui/ssr/web 全 feature 本机测试、native/WASM 严格 Clippy、示例严格
Clippy 及 29 组浏览器测试通过。原有完整差分、输入组合态、SSR adoption、stream、
Owner/查询和部分 Plan 回收测试保留。六份原始/−Oz 三框架产物通过同一验收。

活动 App 的“万行 → 清空 → 三次千行创建/清空”检查中，修改前后都保留 10,000
个存活 Plan Array、110,000 个槽位、110,025 个去重 Node；清空后 Array 和离树行
引用均为零。临时日志与包不构成长期缓存，观察不代表 RSS。
