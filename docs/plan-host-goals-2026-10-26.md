# 类型化 Plan 宿主目标试验（2026-10-26）

本轮把明确的物理操作目标交给 JS 执行，Rust 保留语义模型、身份、校验、提交
顺序和业务回调。它建立在上一轮原始 Plan 部件表之上，减少为了执行一次操作
而取回 Node、读取属性、转换类型、再调用 DOM 的往返。

## 实现边界

第一版有三个专用目标：

| 目标 | Rust 传入 | JS 完成 | Rust 得到 |
|---|---|---|---|
| 写入字段 | 原始实例部件表、目标地址、类型化文本/属性数据 | 顺序写入、移除属性 | 成功或宿主异常 |
| 放置离树部件 | 原始部件地址、Children/RangeEnd 目的地、可选 before | 读取连接状态、解析物理容器、插入 | 已完成 / 已连接需走移动路径 / 缺少 Group 父容器 |
| 移除部件 | 原始实例表、部件地址 | 找到实际父容器并移除 | 成功或宿主异常 |

`NodeId + Part` 到私有物理地址的转换仍由 Rust 的不可变 Layout 完成。宿主目标
只操作创建时保存的 Node，不重新遍历被编辑的 DOM，不根据 slot 重建身份。
每个语义节点的 Entry、完整 NodeId/世代以及 UI、Mapper 两份 Memory 均保留。

首次创建、后续绑定填充本来分布在不同提交阶段。此次保留阶段边界：没有把
所有工作延后到某个最终挂载点，也没有在读取后续 mutation 时提前执行其写入。
因此这不是“一次 run 完成所有行”的协议，仍然按既有提交顺序执行独立目标。

## 有限的字段数据批

输入直接复用 glory-html 已经完成纯映射的 `Edit`。JS 不接收业务 Cage、Role 或
完整 Descriptor，也不再维护一份语义到 HTML 的映射规则。

同一次 HTML Patch 内连续的 Text/Attribute 编辑可形成一个字段目标，最多
16 项。每项明确编码为四个 u32：物理地址、字段种类、名称结束位置、值结束位置。
种类只有文本、设置属性、移除属性。字符串集中传输，位置按 JS 的 UTF-16
code unit 显式计算；没有依赖 Rust 结构体布局或使用 NUL 作分隔符。

单字段目标直接使用对应的类型化 FFI，不为一项写入构造字符串副本和记录数组。
多字段目标借用当前批次的 u32 slice 和字符串。JS 在第一次 DOM 写入前复制
这份最多 256 B 的记录，防止原生事件入口同步回到 WASM 并增长内存时使原视图
失效；字符串已经是 JS 自有值。JS 同步消费，不保存跨调用的借用视图。
超过 16 项按原顺序继续分批。Revision 和 Property 是屏障，交给现有
受控输入、选择、IME、富文本等处理逻辑；不会跨屏障合并或交换次序。

JS 确实在解释有限的数据记录。协议只表达上述宿主目标，没有通用操作栈、寄存器、
跳转、业务表达式或任意函数调用，不提供一门通用 DOM 指令语言。它也不是新的
外部 wire 格式：Rust 和 JS 由同一次 wasm-bindgen 构建配对，未新增公共库 API、
serde 依赖或持久化版本兼容承诺。

## 放置、错误与回收

放置目标先由 JS 检查当前连接状态。如果节点已连接，返回“未执行”，随后使用
原有 Rust 移动路径处理焦点、选择、IME 和 moveBefore。离树节点才直接插入；
没有省略原本为了保护这些状态而做的判断。已连接移动会多一次判断过桥，其小操作
开销必须纳入 benchmark。Group 仍使用原有注释边界，不新增包装元素。

Rust 的 Mapper 仍先完成目标和语义校验，再同步执行宿主目标。每个目标返回后
才更新当前操作的成功 receipt；遇到 JS 异常立即返回，不继续执行后续编辑或
mutation。单个补丁内已经完成的物理字段保留，符合原有宿主故障契约，没有
声称 DOM 操作可以整体回滚。缺少 Group 父容器仍返回原有 InvalidPlacement。

完整销毁继续释放共享实例；部分销毁仍清空原始 Array 对应槽位。新写入和移除
目标无需把 Node 取回 Rust，也不保留额外节点缓存或访问历史。

## 过桥和真实工作

独立计数覆盖完整 WASM imports，并另计生成绑定调用的 WASM exports。诊断包装
不进入正式计时。以千行创建为例，每行现在是克隆、放置、编号文本、标签文本、
class 五个目标，省去三次 Array.get、一次 instanceof_Element，以及分别读取
parentNode/isConnected 和插入的过桥。

| WASM→JS | 修改前 | 修改后 | 变化 |
|---|---:|---:|---:|
| 创建千行 | 11,034 | 5,034 | −54.4% |
| 替换千行 | 13,034 | 6,034 | −53.7% |
| 清空千行 | 2,034 | 1,034 | −49.2% |
| 创建万行 | 110,034 | 50,034 | −54.5% |

千行创建的 JS→WASM externref 分配调用 **1,010 → 10**；替换为 2,010 → 10，
清空 1,010 → 10，万行创建 10,010 → 10。返回结果以完成状态为主，减少了由
parentNode 等返回 Node 导致的分配；malloc 调用仍为 2。没有把导入调用转移成
额外的反向分配调用。

千行创建仍然执行 1,000 次深克隆、9,000 次 setAttribute、2,000 次 nodeValue
和 1,000 次 insertBefore。四项操作的 DOM 方法、属性名、解码次数和解码字节数
均与修改前一致。身份属性仍为 8,000 次，class 为 1,000 次，没有通过少写语义
身份或少创建节点获得成绩。

## 正确性与内存观察

16 个 glory-web 本机测试及 native/WASM 严格 Clippy 通过，glory-html 全 feature
测试与原有完整差分 oracle 也再次通过。新编码测试覆盖非 BMP
字符、中文、引号、反斜线、NUL、空值与移除的区别、顺序、边界上限及属性屏障。
28 组浏览器测试继续验证 CSR、SSR adoption、stream、查询、选择和组合态等路径。

最大 256 节点 Plan 的浏览器探针新增 Role/默认值/字段清除测试，确认多属性目标
不改变原有部件身份。故障注入在一个字段批的 role 写入处抛错：此前 aria-level
已成功写入、之前 mutation 的标签更新保留、之后的标签更新不执行；再次 flush
返回 Faulted。原有跨位图边界的部分销毁、File 多物理部件、实例隔离和监听检查保留。

另一个故障注入在字段批的第一次写入期间执行 WASM memory.grow，确认剩余字段
仍然完成。它在修复前确实失败，暴露了借用 TypedArray 在宿主回调时被分离导致
后缀漏执行的问题；现在使用上述有界记录快照。最初计时、构建产物及失败记录
均保留；正式表格采用修复后的最终产物重新测量。

最初两次单次 GC 的探针未观察到全部弱引用释放，失败记录保留在原始目录。
探针现记录最多五轮 GC 观察，在各轮间结束 JS job；每一轮都严格检查 WASM 表和
实例 Array 不包含退休节点，不放宽强引用断言。最终检查中全部弱引用第一轮即
可回收，故障 App 清理后也没有遗留身份部件。

活动 benchmark 的“创建万行 → 清空 → 三次千行创建/清空”另行检查：

|---|---:|---:|
| 万行时直接 Node externref | 30,054 | 54 |
| 活跃 Plan Array / Array 内 Node 槽位 | 10,000 / 110,000 | 10,000 / 110,000 |
| 可达唯一 Node（去重） | 110,025 | 110,025 |

状态；原始 JS 节点数组仍需保留。

## 体积代价

同轮源快照、相同 release 配置，Binaryen 132.0.0 使用
`-Oz --enable-bulk-memory --enable-reference-types`。JS 包含应用绑定和其引用的
全部相对 JS snippets；WASM 和每份 JS 分别压缩，公共 harness/CSS 不计入。

| Glory 文件 | 修改前 B | 修改后 B | 差额 B |
|---|---:|---:|---:|
| wasm-bindgen WASM | 1,842,536 | 1,849,734 | +7,198 |
| −Oz WASM | 1,408,646 | 1,414,155 | +5,509 |
| −Oz WASM Brotli-11 | 375,219 | 376,702 | +1,483 |
| 应用及依赖 JS | 61,661 | 64,891 | +3,230 |
| JS Brotli-11 | 9,102 | 9,699 | +597 |

有限编码器、宿主目标和回退路径增加了代码，不能把这项工作描述成缩小下载体积。
三框架原始与 −Oz 六份产物都通过同一业务、身份、编辑、清理和画面验收。
