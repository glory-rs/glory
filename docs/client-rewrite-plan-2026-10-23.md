## 5. Glory 问题与改进清单

当前为静态盘点所得候选，后续必须补充最小复现、受影响路径和验收证据。不是已确认的所有框架缺陷，也不是此刻批准扩大语义协议的实现清单。

| 编号 | 观察 | 项目证据/影响 | 后续动作 |
| --- | --- | --- | --- |
| G01 | 路由与浏览器历史需要应用自行组织 | 三项目都依赖 Dioxus router | 比较三个应用的重复逻辑；先明确应用策略与可复用宿主机制边界，再决定是否抽出公共支持 |
| G02 | 缺少富文档语义块 | Paloud `public-site/src/widgets.rs` 的 Legal/DocsView 使用 novel-core 输出，含标题锚点、TOC、表格、代码与链接 | 保留可信富 HTML 的服务器文档组合边界；不能转成纯转义文字或删内容，不宣称已具备跨端富文本/水合 |
| G03 | 文件选择需真实宿主接口 | Paloud 管理通知网关包含证书等文件上传 | 设计浏览器文件选择/读取及取消边界；验证内容、限制、错误与真实上传流程 |
| G04 | 有限控件未覆盖原有 select/表格/对话框 | 三项目的后台筛选、编辑、列表与确认流程 | 盘点必须的交互/键盘/无障碍语义；可用组合控件时验证等价行为，不能仅靠样式冒充控件语义 |
| G05 | SVG 图标与文档属性能力差异 | Paloud frontend-shared 的内联 SVG，public-site 的 ID/脚本/属性 | 评估静态 image 资产和外层文档的适用范围，保留可访问命名；不要无约束开放任意 HTML 注入 |
| G06 | 异步加载/认证生命周期迁移成本 | Dioxus use_resource/use_effect/global state/spawn 的调用方 | 用 Owner/资源/任务明确取消和过期发布；记录重复样板与容易误用的接口，补充最小示例和必要回归 |
| G07 | 新旧文档、示例和构建链可能造成误用 | Glory 活动工作区与旧示例/适配器并存，应用原本使用 dx | 记录实际碰到的入口误导、版本冲突与诊断不足，避免以旧 API 修复新应用 |

每项最终记录格式：现象 → 原项目业务触发 → Glory 最小复现 → 所属层 → 应用解决/框架修复/待实现 → 验证 → 剩余限制。框架修复需同时检查 preflight/direct apply、共享 mapper 与各实际受影响宿主，遵守 Glory AGENTS 的语义边界。
