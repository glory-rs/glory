# Plan 物理部件批处理与过桥分析（2026-10-26）

本轮将千行创建的 WASM→JS 调用 **19,034 → 11,034（−42.0%）**，
但四轮配对测试的创建耗时基本不变。替换和清空的 Script 中位数分别改善约
3.0% 和 2.2%，不足以解释与 Dioxus 的主要差距。此次保留的是对显式 Plan
物理部件的统一所有权和按需取回，不能把调用数下降表述为同等比例提速。

## 19,034 次调用在哪里

独立诊断页面包装所有 WASM imports，并另外包装生成绑定使用的 WASM exports，
同时统计真实 DOM 方法和 TextDecoder。计数、GC、CPU 计时分别运行，正式性能
产物没有这些包装。统计包含实际委托事件、RAF 和焦点同步产生的固定开销。

| 千行创建的 WASM→JS 导入 | 修改前 | 修改后 |
|---|---:|---:|
| JS Array.get，取回 Plan 的物理节点 | 11,000 | 3,000 |
| set_nodeValue | 2,000 | 2,000 |
| instanceof_Element | 1,001 | 1,001 |
| gloryClonePlan | 1,000 | 1,000 |
| parentNode | 1,000 | 1,000 |
| isConnected | 1,000 | 1,000 |
| insertBefore | 1,000 | 1,000 |
| setAttribute | 1,000 | 1,000 |
| 其他事件、焦点、RAF | 33 | 33 |
| 合计 | **19,034** | **11,034** |

每行有八个语义节点、十一个物理部件。原来克隆后立即将全部十一个部件取回
Rust，虽然首次挂载实际只用行根和两个动态 Text。现在只取回这三个，剩余部件
首次被查询、事件、属性更新等操作用到时再取回，每个部件只初始化一次。

| 操作的导入总数 | 修改前 | 修改后 |
|---|---:|---:|
| 创建千行 | 19,034 | 11,034 |
| 替换千行 | 21,034 | 13,034 |
| 清空千行 | 2,034 | 2,034 |
| 创建万行 | 190,034 | 110,034 |

两个方向都计数：千行创建的 JS→WASM `__externref_table_alloc` 仍为 **1,010**，
`__wbindgen_malloc` 仍为 **2**，事件和 RAF 回调各一次。没有通过返回
`Vec<JsValue>` 把导入转移成上万次反向分配调用。

真实 DOM 工作完全相同：千行创建仍有 1,000 次深克隆、9,000 次 setAttribute、
2,000 次 nodeValue 和 1,000 次 insertBefore。TextDecoder 仍调用 5,012 次、
解码 106,056 字节。替换、清空、万行创建的 DOM 计数、属性名和解码字节也逐项一致。

## 类型与生命周期

`browser/plans.rs` 的私有 `Prototype` 同时持有原型和不可变 `Layout`，由同一声明
的存活实例共享。实例保留 `gloryClonePlan` 已经构造的原始节点 Array。每个
`Parts` 仍使用有限的 `Part::{Main,Control,Content,Picker}` 和 `OnceCell<Node>`；
首次取回按不可变地址定位，并不重新查找当前 DOM 的子节点路径。

这样，即使文本前插入了宿主节点、可编辑内容改变、节点移动，延迟取回仍指向
创建时的同一个 Node。新实例不会复制旧实例的编辑、事件监听或身份。普通 Create、
Group、hydration 继续走原有路径；原型预算不足仍执行现有 fallback。

UI 与 Mapper 的两份 Memory、完整 NodeId/世代、全部语义节点、目标/内容/属性校验、
Shape 根检查、Plan 实例检查及成功前缀约定都保留。没有 opcode、通用指令流、
模板解释器、新公共 API、能力裁剪或新增 unsafe Rust。

共享 Array 必须支持部分销毁，否则会由存活兄弟间接保留已销毁节点。实例使用
固定的两份 u32 位图，最多 256 个语义成员；完成观察器和物理移除后，按当前退休
成员清空 Array 中对应槽位。一次完整实例退休不需要调用 JS 清空，所有持有者
释放时整个 Array 自然释放。局部销毁按受影响实例处理，不保存访问历史、业务键
或已退休节点。物理移除失败时仍保留原先优先返回该错误的行为。

## 内存、正确性与体积代价

新浏览器测试使用真实最大规模 Plan：移动并退休 File 和跨越 31/32、63/64、
127/128、254/255 位的成员，拒绝过期更新，再更新存活兄弟并重新实例化。
它验证完整身份、原始文本寻址、独立监听器和原型隔离。仅持有 WeakRef 的 GC
探针同时检查直接 externref 和 Array 内部槽位：22 个退休物理引用全部可回收，
存活共享 Array 内无退休引用；完全销毁后带身份部件引用为零。

同样的独立探针观察活动 benchmark 的“万行 → 清空 → 三次千行创建/清空”：

| 观察项 | 修改前 | 修改后 |
|---|---:|---:|
| 万行时直接 Node externref | 110,054 | 30,054 |
| 万行时活跃 Plan Array | 0 | 10,000 |
| Array 内 Node 槽位 | 0 | 110,000 |
| 可达唯一 Node（两类引用合并去重） | 110,025 | 110,025 |
| externref 表容量（含槽位容量，不是字节） | 132,100 | 66,564 |
| 清空后直接 Node externref | 54 | 54 |
| 清空后 Plan Array / 离树行引用 | 0 / 0 | 0 / 0 |

这是引用组织改变，没有减少实际节点。Rust 每个 Parts 新增实例地址，每个实例
新增共享管理和两个位图，JS 也保留一份 Array；不能由表容量减半推断总内存或 RSS
下降。原型 Layout 随已有有界缓存生命周期共享，不保存过去所有实例。

统一 Binaryen 132.0.0 `-Oz --enable-bulk-memory --enable-reference-types` 后：

| Glory 文件 | 修改前 B | 修改后 B | 差额 B |
|---|---:|---:|---:|
| wasm-bindgen WASM | 1,837,512 | 1,842,564 | +5,052 |
| −Oz WASM | 1,405,359 | 1,408,677 | +3,318 |
| −Oz WASM Brotli-11 | 373,795 | 375,345 | +1,550 |
| 包含相对 JS snippets 的 JS | 60,648 | 61,661 | +1,013 |

这不是体积优化。新生命周期逻辑增加少量代码；保留优化的理由是消除无用的
跨边界取回、统一显式构造的物理部件所有权，而不是追求初始体积。

验证包括 glory-web 全 feature 的 14 个本机测试、native/WASM 全 feature 严格
Clippy、示例严格 Clippy、28 组真实浏览器测试、Sapid 默认/全 feature 检查及
共享 style/core/render/ui/html/ssr 全 feature 测试与严格 Clippy。
三框架原始/−Oz 六份产物均通过相同数据、编辑、身份、清理和画面验收。
